# Session Summary - 2026-02-10

## Problems Solved

### 1. TextRecipe page not returning recipes
**Root cause:** Three issues compounding:
- **ES module ordering bug:** `generateClient()` in `TextRecipe.tsx` ran at module import time, *before* `Amplify.configure()` in `main.tsx` executed. In the original single-file `App.tsx`, both calls were in the same file and ran in order.
- **IAM policy mismatch:** `backend.ts` granted permissions for `claude-sonnet-4-5` but `bedrock.js` was calling `claude-3-sonnet`. Bedrock returned access denied.
- **Silent error handling:** `bedrock.js` response handler crashed on error responses (`parsedBody.content[0]` undefined) instead of handling them gracefully.

**Fixes:**
- Moved `generateClient()` inside the component body so it runs at render time (after Amplify is configured)
- Updated IAM policy ARN in `backend.ts` to match `claude-3-sonnet-20240229-v1:0`
- Added error handling in `bedrock.js` response function with optional chaining

### 2. Loading spinner replacement
- Replaced Amplify `<Loader>` / `<Placeholder>` components with Claude Code-style braille spinner animation (matching hqdev.io)
- Spinner uses `@keyframes spin-braille-content` cycling through braille characters
- Styled with monospace font, amber color (`#f5a623`)

### 3. Background contrast fix
- Added `background-color: rgba(255, 255, 255, 0.85)` to `.app-container` so dark text (`#1a202c`) is readable against the dark body background

### 4. Claude Code update notification
- winget had v2.1.38 (latest in its registry) but npm had v2.1.39
- Resolved by running `npm install -g @anthropic-ai/claude-code@latest`
